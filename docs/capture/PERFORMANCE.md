# 性能与数据丢失边界

## 已测

内存日志：2 万次操作记录 11.37ms（Node.js 24.21.0，`src/app/script/capture/model.test.ts`）。测试同时覆盖过程时钟、撤销分支和 ZIP 往返。

采集关闭时，指针回调只读取状态后返回，不写队列、不读画布、不发网络请求。

采集开启时：

- 指针路径只把小对象放进内存队列。
- IndexedDB 写入在 1 秒定时器里，不在 `pointermove` 里同步等待。
- 画布复制放到笔画结束之后的动画帧；若下一笔已经按下，则放弃这次复制并记下缺口。
- 检查点编码最多排队 2 个，超出后保留操作、丢掉这一张图。

## 未测，不能当成验收

同设备、同画布、采集关闭/开启的人工笔感比较还没有做。约一小时真人创作、真实数位板、长会话内存曲线、回放跳转卡顿和大文件导出时的界面响应都还没有实测。这些列为待验收，不把自动化测试写成真人试采结果。

## 丢失边界

- 崩溃或断电：上次成功写入之后、队列里尚未 flush 的记录会丢。间隔目标是 1 秒。
- 落笔过程中：定时器可以先写已有输入点；整画布读回会等到这一笔结束。
- 刷新：IndexedDB 里已成功的记录还在。Klecks 画布恢复仍走它自己的恢复库，采集续画不会自动把画布画回去。
- 存储不足：写入失败时队列留在内存，面板报错，可以导出。记录不会因为失败被删。
- 网络中断：没有远程上传，所以不存在上传覆盖其他作品。本地提交号重复点击不会新建第二条。
- 页面隐藏：不是休息。过程时钟继续，并记一条不确定的可见性事件。
